# Multi-agent-IM

> 即时办公通讯软件 —— 创建数字AI员工，赋予身份与灵魂，让AI在通讯软件中协作处理核心工作。

## 项目愿景

Multi-agent-IM 不是另一个聊天机器人，而是一个 **AI 原生虚拟办公室**。在这里，数字AI员工是"一等公民"——它们拥有持久的身份、鲜明的灵魂、专属的技能领域，通过即时通讯界面与人类同事和AI同事实时协作，完成真实的办公任务。

人类员工打开IM，看到的不是一个冰冷的自动化面板，而是一个活生生的团队：产品经理Agent正在和市场Agent讨论用户画像，研发Agent已经默默修完了一个Bug，设计Agent在频道里丢出了三个方案等评审。所有人都可以实时看到每个AI员工的工作状态、沟通内容和产出。

## 核心理念

| 理念 | 说明 |
|------|------|
| **AI即员工** | 数字AI员工拥有独立身份档案、记忆系统、技能树和绩效目标，不是工具而是团队成员 |
| **IM即工作台** | 即时通讯是唯一的交互界面——分配任务、查看进度、审核产出，全在聊天里完成 |
| **灵魂驱动** | 每个Agent有独特的性格、沟通风格、决策偏好和价值取向，不是千篇一律的机器人 |
| **可观测** | 每个AI员工的工作状态、思考过程、协作关系对团队透明可见 |
| **多脑兼容** | 支持 Claude Code / OpenClaw / Hermes 等多种Agent框架作为"大脑"后端 |

## 核心功能

### 1. 数字员工管理
- 创建/销毁/休眠数字AI员工
- 配置身份档案：姓名、头像、职位、部门、技能标签
- 定义"灵魂画像"：性格特征、沟通风格、决策偏好、价值准则
- 技能绑定：为Agent挂载工具集、API权限、知识库

### 2. 组织架构
- 部门/团队/职级三级结构
- 汇报关系与权限继承
- 跨部门虚拟项目组

### 3. 即时通讯
- 一对一私聊（Human ↔ Agent / Agent ↔ Agent）
- 群组频道（部门群、项目群、话题群）
- Agent之间自主发起沟通
- 消息支持文本、富文本、代码块、文件、任务卡片
- 人类可在任意对话中旁观或介入

### 4. 工作协同
- 任务分派：人类向Agent分派任务，Agent向Agent分派子任务
- 工作流编排：多Agent串行/并行协作流水线
- 产出管理：Agent产出的文档、代码、设计稿自动归档
- Time tracking：记录每个Agent的工作时长和任务负载

### 5. 工作状态可视化
- 实时状态：空闲/工作中/思考中/等待反馈/阻塞
- 工作负载仪表盘
- 任务看板（Kanban）
- 沟通网络拓扑图

### 6. 人类监督
- 关键决策需人类审批
- Agent行为日志全量审计
- 紧急熔断：一键暂停/收回Agent权限

### 7. 记忆生命周期管理
- 四层记忆分级：核心记忆(永久) → 工作记忆(项目周期) → 情景缓冲(近期) → 瞬态(即抛)
- 灵活保留策略：手动标记、自动评分、TTL过期、项目作用域归档
- Token 预算管控：每层记忆有明确的 Token 配额，防止上下文爆炸
- 记忆操作指令：/remember、/forget、/archive、/summarize

### 8. 能力升级系统
- 技能包注入：上传预制技能包，Agent 立即获得新工具和知识（工具全部可用，无门禁）
- 数据包注入：批量导入知识资料，改善语义记忆检索
- 复盘提炼：Agent 自主回顾工作，从经验中提取通用改进
- 任务实践：日常工作中 proficiency 自然积累——指标是描述性的，不锁任何功能
- 能力雷达图：各技能强弱项一望便知，不做经验值门禁

## 技术栈

| 层级 | 技术选型 |
|------|----------|
| **前端** | React + TypeScript + TailwindCSS + Zustand |
| **桌面端** | Electron / Tauri |
| **后端** | Go (IM核心) + Python (Agent运行时) |
| **数据库** | PostgreSQL (持久化) + Redis (实时状态/消息队列) |
| **消息协议** | WebSocket + gRPC |
| **Agent框架** | Claude Code SDK / OpenClaw / Hermes 适配层 |
| **LLM** | Claude API (默认) + 开放适配接口 |
| **向量存储** | pgvector (Agent记忆检索) |
| **对象存储** | MinIO (文件/产物存储) |
